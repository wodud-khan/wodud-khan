## Featured Project

### [SDET Playwright Quality Engineering Portfolio](https://github.com/wodud-khan/sdet-playwright-framework)

[![Quality Pipeline](https://github.com/wodud-khan/sdet-playwright-framework/actions/workflows/quality.yml/badge.svg?branch=main)](https://github.com/wodud-khan/sdet-playwright-framework/actions/workflows/quality.yml)

A focused quality-engineering portfolio built around a controlled FastAPI and PostgreSQL
order application.

The project demonstrates:

- A 28-test architecture covering unit, REST API, JSON contract, direct database,
  integration, UI, and end-to-end testing
- Playwright automation across Chromium, Firefox, and WebKit
- A complete UI-to-API-to-PostgreSQL workflow
- Run- and worker-aware test data with exact-record cleanup
- Bounded parallel execution using pytest-xdist
- Docker Compose orchestration with application and database health checks
- Ruff, Mypy, locked Python dependencies, and GitHub Actions quality gates
- Failure diagnostics including Playwright traces, screenshots, video, browser events,
  HTML/JUnit reports, and application, PostgreSQL, and Compose logs
- Passing pull-request and post-merge `main` workflows

## How I Approach Quality

- Start with product risk and expected user behavior rather than tool selection
- Separate unit, API, data, integration, UI, and E2E intent
- Automate stable, repeatable, high-value coverage
- Use unique test data and narrowly targeted cleanup
- Diagnose whether failures originate in the product, test, data, environment, or pipeline
- Treat AI-generated code, tests, and documentation as drafts requiring engineering review
- Base technical claims on executed evidence rather than configuration alone
